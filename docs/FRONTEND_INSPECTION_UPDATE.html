الفحص الفني

ميزة جديدة: الفني بيسجّل فحص للعربية جوه الفاتورة، والفحص بيتطبع للعميل. كل المسارات تحت /api/v1/center.

مفيش حاجة موجودة اتكسرت. كل التغييرات إضافة: 5 APIs جديدة، وحقل جديد inspection_summary في الفاتورة، وصلاحية جديدة orders.inspect.

1. الفكرة

  • كل فاتورة ليها فحص واحد بس، وهو اختياري. بيتفتح من شاشة الفاتورة.
  • قائمة الفحص ثابتة لكل المراكز: 8 أقسام، وفيهم 58 بند.
  • كل بند ليه حالة من التلاتة دول، ومعاها ملاحظة اختيارية:
    • 🟢 ok سليم
    • 🟡 attention يحتاج متابعة
    • 🔴 urgent لازم يتغير
    والبند اللي مالوش حالة بيتحسب "لم يُفحص".
  • على الفحص كله: خانة لنتيجة جهاز كشف الأعطال، وخانة ملاحظات.
  • فاتورة فحص بس: مفيش نوع جديد للفاتورة. هي فاتورة عادية بندها الوحيد خدمة "فحص فني"، وهي من الخدمات الاعتيادية الافتراضية، فهي موجودة عند كل مركز. شوف تقرير الخدمات الاعتيادية. علشان كده الدفع والمديونية وواتساب شغالين عليها عادي.

2. الـ APIs

الـ APIالصلاحيةبيعمل إيه
GET/inspection/checklistorders.viewالأقسام والبنود بأسمائها حسب الـ header lang. الشاشة بتترسم منها
GET/orders/{id}/inspectionorders.viewفحص الفاتورة، أو data: null لو مفيش فحص
PUT/orders/{id}/inspectionorders.inspectحفظ الفحص، سواء أول مرة أو تعديل
DELETE/orders/{id}/inspectionorders.inspectمسح الفحص
GET/orders/{id}/inspection/printorders.viewoutput=json (الافتراضي) أو output=pdf بمقاس A4

  { "key": "transmission", "label": "ناقل الحركة", "items": [ ... ] },

ترتيب الأقسام: المحرك، ناقل الحركة، الفرامل، العفشة والتوجيه، الكهرباء والتكييف، الكاوتش، اختبار القيادة، الشاسيه والبودي. ينفع كل قسم يبقى tab زي شاشة المنافس.

الحفظ

PUT /orders/15/inspection
{
  "items": [
    { "item": "engine_oil", "status": "ok" },
    { "item": "front_pads", "status": "urgent", "note": "التيل خلصان" },
    { "item": "battery", "status": "attention" }
  ],
  "diagnostic_result": "P0300 - Random misfire",
  "notes": "محتاجة متابعة بعد شهر"
}
مهم: كل حفظ بيستبدل البنود القديمة كلها. ابعت كل البنود اللي ليها حالة كل مرة، مش البند اللي اتغير بس. أي بند مش مبعوت هيتحسب "لم يُفحص"، وده ينطبق كمان على diagnostic_result وnotes.
الحقلالقواعد
itemsمطلوب ولازم يبقى array، وينفع يبقى فاضي []
items.*.itemkey بند من قائمة الفحص، ومينفعش يتكرر
items.*.statusok أو attention أو urgent
items.*.noteاختياري، لحد 500 حرف
diagnostic_resultاختياري، لحد 5000 حرف
notesاختياري، لحد 2000 حرف

3. الفحص في الفاتورة

GET /orders/{id} بقى فيه حقل جديد:

"inspection_summary": { "ok": 12, "attention": 3, "urgent": 1, "not_checked": 42 }   // أو null لو مفيش فحص

استخدمه علشان تعرض في شاشة الفاتورة زرار "إضافة فحص" لو القيمة null، أو "عرض الفحص" ومعاه الأعداد الملونة لو فيه فحص.

4. القواعد

الحالةاللي يحصل
فاتورة مفتوحةأي حد معاه orders.inspect يقدر يحفظ
فاتورة مقفولةمحتاجة كمان orders.edit_completed، وإلا يرجع 403. الفني العادي ما بيشوفش الفواتير المقفولة أصلًا، فبيرجعله 404
فاتورة ملغية أو رصيد افتتاحيمقفولة، ويرجع 422
طباعة أو مسح فاتورة مفيهاش فحص404 ومعاه رسالة "الفاتورة دي مفيهاش فحص فني."
فاتورة من مركز تاني404

الصلاحية الجديدة orders.inspect اسمها في شاشة الأدوار "تسجيل الفحص الفني". الأدوار الافتراضية كلها بتاخدها: المالك، والكاشير، والفني والكاشير، والفني.

5. الطباعة

  • output=pdf بيرجّع PDF مقاس A4 بالعربي. فيه:
    • بيانات المركز والعميل والعربية والعداد
    • ملخص بالألوان
    • البنود اللي اتفحصت بس، متقسمة على الأقسام
    • نتيجة جهاز كشف الأعطال والملاحظات
    • مكان لتوقيع الفاحص والعميل
  • output=json بيرجّع نفس البيانات لو حابب ترسم التقرير بنفسك.
  • العداد بيتاخد من odometer بتاع الفاتورة، فخلّي الفني يدخّله في الفاتورة.

6. المطلوب من الفرونت

  1. شاشة الفحص من الفاتورة:
    • tab لكل قسم من /inspection/checklist.
    • كل بند فيه 3 أزرار حالة ملونة، وخانة ملاحظة.
    • تحت الأقسام خانة لجهاز كشف الأعطال، وخانة ملاحظات.
  2. زرار حفظ يبعت كل البنود اللي ليها حالة في PUT واحد.
  3. في شاشة الفاتورة اعرض inspection_summary، وزرار "طباعة الفحص".
  4. اخفي أزرار التعديل لو المستخدم معهوش orders.inspect (من auth/me)، أو لو الفاتورة مقفولة وهو معهوش orders.edit_completed.

الأمثلة الكاملة موجودة في Postman collection تحت مسارات inspection.
