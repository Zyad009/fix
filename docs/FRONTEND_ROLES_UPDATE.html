الأدوار والصلاحيات

تحديث الباك إند — المالك بقى يعمل أدوار لمركزه ويختار صلاحيات كل دور. كل المسارات تحت /api/v1/center.

الشاشات الموجودة مش هتتكسر. role في الحسابات والموظفين لسه بنفس الشكل {label, value}، والقيم القديمة (owner، cashier، technician_cashier، technician) لسه شغالة زي ما هي. المطلوب: شاشة جديدة لإدارة الأدوار، وتحديث صغير في اختيار الدور.

1. ملخص التغييرات

جديدإدارة الأدوار

المالك يقدر يضيف دور، ويعدّل اسمه وصلاحياته، ويمسحه. كل مركز ليه أدواره لوحده.

اتغيرقائمة الأدوار

options.roles بقت جاية من أدوار المركز نفسه، فممكن يبقى فيها أدوار المالك عملها، زي role_12.

اتغيرالفني والكاشير

technician_cashier بقى يقدر يعدّل الفاتورة المقفولة، لكن لسه ما يقدرش يلغيها.

زي ما هوتسجيل الدخول

auth/me بيرجع permissions زي الأول. اعتمد عليها في إظهار وإخفاء الأزرار، مش على اسم الدور.

2. الـ APIs الجديدة

كلها محتاجة صلاحية roles.manage، والصلاحية دي للمالك بس. أي حد غيره هياخد 403، فالقائمة بتاعتها تظهر للمالك بس.

3. شكل الدور (Role)

{
  "id": 14,
  "key": "role_14",           // ده اللي بيتبعت في role لما تعمل حساب أو موظف
  "name": "مشرف ورشة",
  "is_owner": false,
  "is_default": false,        // true للأدوار الأربعة اللي المركز بيبدأ بيها
  "acts_as_technician": true,
  "permissions": ["customers.view", "orders.view", "..."],
  "users_count": 0            // في list/show/store/update
}
  • key بيتعمل لوحده ومش بيتغير أبدًا، حتى لو الاسم اتغير. الأدوار الافتراضية مفاتيحها owner وcashier وtechnician_cashier وtechnician، والأدوار الجديدة مفتاحها role_{id}.
  • دور المالك permissions بتاعته فيها كل الصلاحيات، ومن ضمنها roles.manage.

4. قائمة الصلاحيات

GET /roles/permissions بيرجع مجموعات، والأسماء جاية حسب الـ header lang:

{
  "data": [
    { "key": "settings", "label": "الإعدادات والحسابات",
      "permissions": [ { "key": "settings.manage", "label": "تعديل إعدادات المركز" }, ... ] },
    { "key": "orders", "label": "الفواتير", "permissions": [ ... ] },
    ...
  ]
}

اعرضها زي ما هي. القائمة دي مش فيها roles.manage لأنها ما ينفعش تتدي لأي دور غير المالك.

6. الحسابات والموظفين

الـ APIاللي اتغير
GET /optionsاتغيرroles بقت أدوار المركز من الداتابيز، بنفس الشكل [{label, value}]. ممكن يبقى فيها أدوار جديدة، وممكن دور افتراضي يختفي لو المالك مسحه، فما تكتبش القائمة ثابتة في الفرونت.
POST/PUT /usersrole = key أي دور في المركز. دور من مركز تاني بيرجع 422.
GET /users?role=الفلتر بقى بياخد أي key، مش بس الأربعة القديمة.
POST/PUT /employeesaccount.role = أي دور غير المالك. شيل owner من الاختيارات هنا.
حماية حسابات المالك: أي حساب غير المالك، حتى لو معاه users.manage، ما يقدرش يعمل حساب مالك، ولا يعدّل حساب مالك (ومن ضمنه الباسورد)، ولا يوقّفه. كل ده بيرجع 403. في شاشة الحسابات، لو المستخدم الحالي مش مالك، اخفي اختيار owner وأزرار التعديل والإيقاف على حسابات المالك.

7. الفني والكاشير يعدّل فاتورة مقفولة

technician_cashier أخد صلاحية orders.edit_completed، فيقدر يضيف ويعدّل ويمسح بنود فاتورة مقفولة، ويعدّل الخصم والملاحظات، زي المالك.

  • الإلغاء (orders.cancel_completed) لسه للمالك بس.
  • اعتمد على permissions من auth/me علشان تظهر أزرار التعديل على الفاتورة المقفولة، مش على اسم الدور. كده أي دور جديد ياخد الصلاحية دي هيشتغل لوحده.

8. الأخطاء

كلها بنفس الشكل المعتاد {status, msg, data}، وmsg جاي بلغة الـ header lang.

9. المطلوب من الفرونت

  1. شاشة الأدوار (للمالك بس): جدول بالأدوار فيه الاسم وعدد الحسابات، وفورم فيه الاسم و"يعتبر فني" وصلاحيات متقسمة مجموعات من /roles/permissions.
  2. اختيار الدور في الحسابات والموظفين: هات القائمة من options.roles كل مرة، وما تكتبهاش ثابتة. في الموظفين شيل owner، وأي دور غير المالك محتاج اختيار فرع.
  3. شاشة الحسابات: لو المستخدم مش مالك، اخفي اختيار المالك وأزرار التعديل والإيقاف على حسابات المالك.
  4. الفاتورة المقفولة: أزرار التعديل تظهر حسب orders.edit_completed، والإلغاء حسب orders.cancel_completed.
  5. سجل العمليات: فيه نوع جديد auditable_type = "role"، فمحتاج يتعرض باسم "دور".

التفاصيل الكاملة والأمثلة موجودة في Postman collection (postman/Dawar.postman_collection.json) تحت مسارات roles.
