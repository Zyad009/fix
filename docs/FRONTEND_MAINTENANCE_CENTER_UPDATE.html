تحديث الـ API: المراكز والدخول بالـ username

للفرونت إند (شاشات المركز ولوحة الأدمن) · 6 نوفمبر 2026

فيه breaking changes. النسخة دي من الـ API لازم تتنشر هي والفرونت في نفس الوقت. لو الباك اتنشر قبل الفرونت، بيانات المركز في شاشات المركز مش هتظهر، ولوحة الأدمن هتطلع 404 في كل شاشات المراكز.

الخلاصة في سطور

  • Breaking رد الدخول و me: المفتاح tenant بقى maintenance_center.
  • Breaking لوحة الأدمن: كل مسارات /admin/tenants بقت /admin/maintenance-centers.
  • تغيير سجل العمليات: نوع السجل tenant بقى maintenance_center.
  • جديد الدخول بـ username كبديل للإيميل.
  • جديد حقل username في المستخدمين، وحسابات الموظفين، ومالك المركز الجديد.
  • من غير شغل روابط الصور الجديدة بقت تحت maintenance-centers/، والفرونت مش محتاج يغيّر حاجة.

1. رد الدخول و me Breaking

بيانات المركز في الردين دول بقت تحت مفتاح جديد. محتوى المركز نفسه ما اتغيرش (id و name و logo_url وإعدادات الواتساب وغيرهم).

POST/api/v1/center/auth/login
GET/api/v1/center/auth/me

قبل

{
  "data": {
    "token": "...",
    "user": { ... },
    "tenant": { "id": 1, "name": "مركز أ", ... },
    "branches": [ ... ],
    "permissions": [ ... ]
  }
}

بعد

{
  "data": {
    "token": "...",
    "user": { "username": "ahmed", ... },
    "maintenance_center": { "id": 1, "name": "مركز أ", ... },
    "branches": [ ... ],
    "permissions": [ ... ]
  }
}
متنساش اللي متخزن عندك. لو بتحفظ رد الدخول في localStorage أو في الـ store، المستخدمين اللي داخلين بالفعل عندهم نسخة قديمة فيها tenant. أبسط حل: أول ما الصفحة تفتح، نادي GET /auth/me وحدّث المحفوظ. التوكنات القديمة لسه شغالة، ومفيش حد هيضطر يسجل دخول تاني.

ابحث في الكود عن: data.tenant و .tenant. و tenant?. و ['tenant'].

3. سجل العمليات تغيير

GET/api/v1/center/audit-logs

قيمة auditable_type للسجلات الخاصة بالمركز نفسه بقت maintenance_center بدل tenant، في الرد وفي الفلتر ?auditable_type=. السجلات القديمة اتحدّثت في قاعدة البيانات.

لو عندك dropdown لأنواع السجل أو ترجمة للنوع، غيّر القيمة دي. باقي الأنواع (order و payment و user وغيرهم) زي ما هي.

4. الدخول بالـ username جديد

POST/api/v1/center/auth/login

المستخدم يقدر يدخل بالإيميل زي الأول، أو بالـ username لو اتعمله واحد. الدخول بالإيميل لسه شغال من غير أي تغيير.

بالإيميل (زي الأول)

{
  "email": "owner@dawar.test",
  "password": "secret123"
}

بالـ username

{
  "username": "ahmed",
  "password": "secret123"
}
القاعدةالتفاصيل
الحقوللازم email أو username، ومعاهم password. لو بعت الاتنين، الإيميل هو اللي بيتستخدم.
حالة الحروفمش بتفرق: Ahmed و ahmed نفس المستخدم.
المحاولات5 محاولات في الدقيقة، وبعدها 429.
دخول الأدمنما اتغيرش. /admin/auth/login لسه بالإيميل بس.

اقتراح لشاشة الدخول

خانة واحدة باسم "الإيميل أو اسم المستخدم". لو القيمة فيها @ ابعتها email، ولو مفيهاش ابعتها username. ده آمن لأن الـ username مينفعش يكون فيه @.

const body = identifier.includes('@')
  ? { email: identifier, password }
  : { username: identifier, password };

ردود الخطأ

الحالةcodeالسبب
401invalid_credentialsالمستخدم مش موجود أو كلمة السر غلط. الرسالة واحدة في الحالتين عن قصد.
403account_inactiveالحساب أو المركز موقوف.
422422مفيش إيميل ولا username، أو الإيميل مش بصيغة صحيحة.
429—أكتر من 5 محاولات في الدقيقة.

5. إضافة وتعديل الـ username جديد

القاعدةالتفاصيل
إجباري؟لأ، اختياري في كل مكان. الحسابات الحالية username بتاعها null.
الطولمن 3 لـ 50 حرف.
الحروف المسموحةحروف إنجليزي وأرقام و - و _ بس. ممنوع المسافات والعربي و @.
التكرارفريد على مستوى كل المراكز مش المركز بس، ومن غير فرق في حالة الحروف. لو اسم مستخدم في مركز تاني، هيرجع 422.

Regex للتحقق في الفرونت قبل الإرسال: /^[A-Za-z0-9_-]{3,50}$/

المستخدمين

POST/api/v1/center/users
PUT/api/v1/center/users/{id} 

{
  "name": "أحمد",
  "username": "ahmed",
  "email": "ahmed@dawar.test",
  "password": "secret123",
  "role": "cashier",
  "branch_id": 1
}
  • التعديل: تقدر تغيّر username و email من نفس الطلب، وتبعت الحقل اللي اتغير بس.
  • المسح: {"username": null} بيمسح الـ username.
  • لو ما بعتهوش: الـ username بيفضل زي ما هو.
  • البحث: GET /users?q= بقى بيدوّر في الـ username كمان.
  • الرد: فيه username في كل رد مستخدم (القايمة والتفاصيل والدخول و me).

حساب الموظف

POST/api/v1/center/employees
PUT/api/v1/center/employees/{id} 

{

  "account": {
    "username": "hassan",
    "email": "hassan@dawar.test",

الرد فيه account.username:

"account": { "id": 7, "username": "hassan", "email": "hassan@dawar.test", "role": { ... }, "is_active": true }

6. روابط الصور من غير شغل

الصور الجديدة (لوجو المركز، وصور المنتجات، وصورة الشاسيه) بقت بتتخزن تحت maintenance-centers/ بدل tenants/:

قبل:  https://.../storage/tenants/1/vehicles/AbC123.jpg
بعد:  https://.../storage/maintenance-centers/1/vehicles/AbC123.jpg
الحقول logo_url و image_url و vin_image_url بترجع الرابط كامل، فاستخدمها زي ما هي. أي صورة قديمة هتفضل برابطها القديم وشغالة. ما تبنيش رابط الصورة بنفسك من الـ id أو من المسار.

7. شكل الأخطاء (للتذكير)

ما اتغيرش، بس مهم في شاشات الـ username:

خطأ validation (422)

{
  "status": 0,
  "code": 422,
  "message": "username مستخدم بالفعل.",
  "data": null
}

الرسالة بتيجي من message، وبتكون أول خطأ بس.

باقي الأخطاء

{
  "status": false,
  "msg": "البريد الإلكتروني أو كلمة المرور غير صحيحة.",
  "code": "invalid_credentials"
}

الرسالة من msg، و code موجود أحياناً.
